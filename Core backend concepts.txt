Concurrency - 1: Introduction to Processes and Threads


- code > compile > stored in HDD > in .exe format > run that file > code starts executing in RAM > program under execution > process

- process is a program under execution
- a single process has a Programmable Controller Block inside of a RAM 
- PCB has a register, data bus, instruction set, heap and stack memory 

- a single process has many threads 
- a thread is a basic unit of CPU execution
- CPU executes a thread not process

- in java you always have one main thread running
- each thread has its own stack and program counter
- so when many threads are running they dont wait for each other to get finished
- they run in a async manner
- all threads share the heap memory

- threads are quite lightweight because they do not have much overhead to them 
- threads do not have heap data, instructions associated with them hence you just have to run them

- refer to the diagrams in the lecture pdf for clarity
- threads can communicate with each other using heap memory and different mechanisms like locks, semaphores, etc.

- context switching happens inside of a CPU where registers, counters are present not inside of RAM
- if there are many threads and one thread does some work and it preempts (stops and moves to next one) to the next 
- next one does the same thing and preempts to its next thread
- in such manner many threads work together

-  in context switching we store and restore the state so that later we can pick up from where we left
- if there are many threads running we can get a large amount of context switching which can be noticeable
- otherwise context switching takes negligible time in a process
- 8 threads per one core is a standard that is followed in industry

- you have to choose moderate switching. Not too less or too more switching to get good performance and user experience

- parallelism mean doing many things at the same time in multi core CPU's
- concurrency means doing many things step by step in a given time to reach a destination
- this happens in single core CPU

- without context switching there is no concurrency
- concurrency is an illusion of parallelism 
- this illusion needs context switching

- concurrency can happen on multiple core and single core
- parallelism needs multiple core
- it cannot happen on single core

- concurrency is always accompanied by parallelism in multi core CPU
- they work together to get the best performance out of each thread

- threads are executed in asynchronous manner

- Runnable is the interface that acts like a intermediary between your class and thread object
